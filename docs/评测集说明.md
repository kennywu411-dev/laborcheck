# 评测集说明（laborcheck v1.0.2）

文件：`data/laborcheck-v1.jsonl`，元信息：`data/laborcheck-v1.meta.json`。

## 设计

- 题目全部构造：合同条款、offer、公司和人物都是生成器按模板构造的，不来自任何真实合同或真实个人。
- 标准答案由规则引擎计算：生成器调用 `laborcheck.rules` 中的函数得到结论、金额和依据，答案与依据一一对应，可复现（固定种子 20260）。
- 三种题型：
  - 合法性判断（`verdict`）：给出条款或情形，判断合法或违法。
  - 金额计算（`amount`）：计算金额或天数。误差容忍：精确计算题 ±1 元（天数题必须完全一致）；税后到手和多 offer 对比这类全年累计、各项分别取整的题 ±20 元。
  - 条款改写（`rewrite`）：先判断合法性；违法时给出改写后的条款，并给出一个关键数值（如改写后的试用期月数、试用期工资、违约金上限），按约束判分（如 `≤ 2`、`≥ 8000`），三项（结论、数值、改写文本）都满足才算对。
- 开发集与留出集：按（主题，题型）分层，每层随机抽 30% 作为留出集（种子 20261）。调试提示词、工具描述时只看开发集，留出集留到最后报告。

## 标签

- `needs_local_data`：答对需要知道题面没给出的地方数据（如最低工资、社保基数上下限、社平工资、地方竞业限制标准），共 80 题。
- `params_given`：同一类情形把地方参数直接写在题面里，用来区分"不知道地方数据"和"不会算"，共 31 题。
- 其余 228 题只依赖全国性法律和通用计算。
- `trap`：题目命中的易错点，例如：
  - `boundary` / `just_below_boundary`：合同期限恰好一年、三年，或差一个月（"以上"含本数）。
  - `date_range`：合同期限用起止日期表示，需要自己算出月数。
  - `min_wage_binding`：试用期工资或竞业限制补偿被最低工资托底。
  - `base_cap` / `base_floor`：社保公积金基数被上下限截取。
  - `high_wage_cap` / `no_12_year_cap`：经济补偿三倍封顶时年限最高 12 年；不封顶时没有 12 年上限。
  - `bonus_cliff`：年终奖 36001 元、144001 元这类多 1 元多缴上千元的临界点。
  - `cumulative_bracket`：累计预扣法跨档月份。
  - `local_rule`：深圳竞业限制补偿不低于 50% 的地方规定。
  - `interp_2`、`waiver_invalid`：2025 年 9 月起施行的劳动争议司法解释（二）新增规则。

## 计算口径

题面没写明时，统一按以下口径（也写在技术报告的局限部分）：

- 月计薪天数 21.75 天，小时工资 = 月工资 ÷ 21.75 ÷ 8，加班费一次算出再四舍五入到分。
- 社保每个险种分别按"基数 × 比例 + 固定额"四舍五入到分再相加；公积金按分计算（上海实际按元取整，全年差额在容忍范围内）。
- 社保公积金基数按题面月工资截取上下限；税后到手按全年月薪不变计算，年终奖按题面要求的方式计税。
- 试用期工资下限只比较"约定工资的 80%"和最低工资，不涉及本单位同岗位最低档工资；按题面要求直接比较应发工资。
- 新入职当年年休假按"（剩余日历天数 ÷ 365）× 全年天数"折算，剩余天数含入职当天，不足 1 天的部分不计。
- 未签书面劳动合同的二倍工资按整月计算。

## 质量控制

- 规则引擎有单元测试覆盖边界情况（`tests/`）。
- 标准答案经过独立复算抽检，记录见 [抽检/抽检记录.md](抽检/抽检记录.md)。
- 城市数据每一项都附官方来源，见 [数据来源](数据来源.md)。

## 迁移到其他评测平台

每行字段为 `id / input / expected / tags / split`，打分逻辑在 `src/laborcheck/bench/scoring.py`，只依赖标准库，可以直接移植。
